# 监控范围不改变资源的审阅能力

监控范围只决定资源是否纳入，资源的内容能力决定如何审阅。进入有效范围后，能够安全表示为文本的资源沿用完整文本基线和现有 Diff、块级及文件级 Keep/Revert、Undo、review token、脏缓冲区和 Git 上下文保护；资源是否被 Git 跟踪、是否曾被 `.gitignore` 或普通规则排除，不改变这些能力。无法安全文本审阅的 binary、BOM、invalid UTF-8、oversized 或其他不透明资源只保存存在性和内容身份，提供信息、打开当前文件和不透明变化确认，不提供文本写回或非文本内容恢复。

全工作区模式可能因此把 `.env`、私钥文本、生成配置和依赖源码的完整文本基线保存到扩展宿主的本地 VS Code storage，并允许用户主动执行现有 Revert。每次开启必须披露这一点；DiffTracker 不建立疑似敏感文件分类器、不因文件名自动排除或降级，也不以少量命名启发式制造已保护的安全假象。用户通过工作区显式排除控制敏感范围。

0.8.0 沿用本地未加密 session 存储：数据不上传、不写入项目或 Git，但 storage 不等于加密保险库。显式排除会移除活动 session 中对应路径的数据，却不承诺安全擦除 last-good、归档、日志、文件系统残留或外部备份；加密存储是独立的未来安全设计，不作为全工作区模式的隐式前提。
