# 使用规则模式和全工作区模式定义监控范围

Code Diff Tracker 采用工作区级的两种监控范围模式，且默认使用规则模式。规则模式应用普通忽略规则，并允许显式包含覆盖这些普通规则；全工作区模式忽略普通忽略规则，将工作区内全部可监控资源纳入范围。两种模式都继续遵守 DiffTracker 显式排除和不可监控边界，优先级固定为“不可监控资源 > 显式排除 > 显式包含 > 普通忽略规则”；全工作区模式等价于对全部可监控资源作隐式包含，但不覆盖前两层。

该设置只在当前工作区生效，不作为跨项目全局默认。`.git` 内部元数据、工作区外或通过链接逃逸工作区的目标、非文件资源和 DiffTracker 自身临时操作路径属于不可监控资源；依赖、构建输出、缓存目录和可能包含秘密的普通工作区文件不因名称自动成为不可监控资源。开启全工作区模式因此可能纳入 `.env`、私钥或生成物，用户应使用显式排除控制范围。

范围开关、显式包含和显式排除均采用工作区级配置，多根工作区由同一范围模式控制。范围编辑界面写入当前工作区，不再把新编辑结果写入 Global 配置。旧版 Global `watchExclude` 在用户完成迁移决定前继续作为保护性排除生效；首次使用新版范围设置时提示将其复制到当前工作区，已有 Workspace 值不自动覆盖，拒绝导入也不修改或删除 Global 值。导入后当前工作区不再持续跟随 Global 变化。该决定仅涉及监控范围设置，不顺带改变显示、配色或打开方式等无关设置。

“监控”只维护资源相对于审阅基线的当前待审变化，不保存逐次写入事件、多个历史版本或非文本内容副本。多次修改最终恢复到基线时，可以回到无待审变化。

设置值表达范围请求，而不是绕过确认的授权。每次规则模式切换为全工作区模式，无论来自侧边栏、设置 UI、直接编辑配置还是打开他人提供的工作区，都必须获得当前工作区的明确确认；已确认且范围未变化的重载不重复询问。确认前界面显示“待确认”，不得显示为已开启。范围模式不改变录制状态：停止录制时可以预设范围，但直到下一次明确开始录制才建立基线或监听。
