# 使用枚举模式和原子范围配置

监控范围模式由工作区设置 `diffTracker.monitoringScope` 表达，值为 `rules` 或 `wholeWorkspace`，默认 `rules`；侧边栏可以继续用 Off/On 呈现，但不再增加含义重复的布尔设置。显式包含使用工作区相对的字面文件或目录路径，目录包含后代；显式排除保留 gitignore 风格匹配能力，但禁止 `!` 否定规则，重新纳入资源只能通过显式包含完成。排除始终高于包含。

每条包含或排除规则明确选择作用于所有工作区根或一个指定根。配置使用结构化条目，而不是把根名称和路径编码到同一个模式字符串；多根工作区 UI 创建规则时必须让用户明确选择“All workspace folders”或具体根。指定根以 VS Code 展示的 WorkspaceFolder 名称引用，名称必须唯一；名称重复时禁止创建或应用根级规则，根被重命名或移除时相应规则变为无效，不根据磁盘路径、数组序号或相似名称猜测新指向。单根工作区优先使用“All workspace folders”，避免无意义绑定目录名。

任何绝对 include、越出工作区的 include、无效或否定 exclude、不存在或歧义的根、缺失字段和无法安全解析的路径都会使整份范围请求无效。无效配置不部分生效，继续使用上一份有效监控范围，并逐项显示错误；尤其不能静默忽略无效 exclude。一次设置保存中的模式、include 和 exclude 构成单一范围配置版本，只有整份配置的校验、必要确认、扫描和持久化全部成功后才能原子替换当前有效范围。异步结果只能发布到其发起时的配置版本，较新的编辑会使旧结果失效。

直接编辑工作区设置产生范围请求，但不自动获得确认。用户取消或尚未完成确认时，扩展不改写 `.vscode/settings.json`，界面显示待确认范围并继续保持上一有效范围；用户可稍后确认、自行修正设置，或显式执行“恢复为有效配置”。若新的显式排除命中已有审阅，在等待确认期间暂停受影响路径的新读取和基线推进；确认后应用排除并清理活动状态，取消后由用户修正请求，恢复监控时将等待期间的证据缺口保守表示为未核验。

旧版 Global `watchExclude` 通过显式的一次性工作区迁移处理。在某工作区完成迁移前，旧规则继续按原有完整语义生效，以防升级后敏感路径意外进入范围；兼容模式不能同时启用新版显式包含或全工作区模式。迁移预览将普通正向规则转换为 Workspace 排除，将无 glob 的简单否定路径建议转换为显式包含；带 glob 的否定规则和与既有 Workspace 规则冲突的项必须由用户处理。全部不兼容项解决并确认后，原子写入新版 Workspace 配置并标记该工作区迁移完成，此后不再读取 Global 值。扩展永不修改或删除旧 Global 配置，其他未迁移工作区继续受其保护。
