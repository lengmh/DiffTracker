# 区分普通范围收缩与显式排除的待审处置

每次从规则模式开启全工作区模式，都要求用户明确确认，并列出全部工作区根和忽略规则失效、敏感文本可能进入本地审阅基线的风险。范围扩展以新纳入资源的稳定当前状态建立基线，不将已有资源伪装为历史新增；扫描期间的变化、不稳定读取和未知覆盖保留为待审或未知状态，不覆盖既有 before-image。新范围必须在基线状态成功持久化后才视为正式生效。

关闭全工作区模式属于普通范围收缩：已离开正常监控范围的待审资源转为“保留审阅”，仅继续对这些具体路径进行必要核验，不再扫描其原目录中的其他被忽略文件。待审变化被确认、明确清除或核验为已恢复基线后，释放该路径；界面标明“范围外保留审阅”，避免把过时状态伪装成当前状态。相比立即丢弃待审项、冻结最后观察结果或禁止退出，这保留了用户尚未处理的工作，也允许退出高覆盖模式。

新增 DiffTracker 显式排除表达更强的停止监控意图。若命中已有待审项，应说明放弃审阅的数量和路径，并经用户确认后移除相关待审状态、停止监控；取消则不应用该排除变更。该操作不修改或删除工作区文件，也不改 Git 数据。历史 session 副本和 Undo 数据是否仍保存该路径，以及手动编辑设置时如何确认，留待后续问题明确，不将“停止监控”等同于“已擦除历史内容”。

显式排除生效后，从活动会话中移除该路径的审阅基线、待审状态和恢复数据；包含多个资源的恢复记录只移除被排除路径，不破坏其他资源的恢复能力。重新纳入时建立新的审阅基线，不自动恢复已放弃的旧审阅。既有 last-good、归档、日志、文件系统残留或外部备份不属于该操作的安全擦除保证，确认文案必须明确这一限制。

范围切换是持久化事务：只有新范围的必要确认、基线准备和 session 保存全部成功后，才替换当前有效监控范围并报告成功。准备或保存失败时继续使用原范围和原基线，保留切换期间观察到的变化证据，并提供明确原因和手动重试入口；不清空旧 session，不降级为仅内存生效，也不循环自动重试。

直接编辑设置产生的显式排除在确认前属于待确认范围，不立即删除活动审阅数据。为避免用户已经请求排除后继续采集该路径，DiffTracker 暂停其新读取和基线推进；确认后完成清理，未确认或取消时不自动重写配置。恢复旧有效范围时，对暂停期间可能发生的变化保守标为未核验。

录制中的范围准备可以由用户取消。取消使该范围配置版本的未完成异步工作失效，释放本次新建的临时监听与候选状态，不发布部分基线，不修改或删除工作区文件；旧有效范围继续生效，准备期间已观察到的变化证据必须保留。设置中的范围请求不因此自动改写，界面继续显示待确认或提供“恢复为有效配置”操作。

普通范围收缩时，已经离开范围且没有待审变化的资源立即从活动 session 释放；存在待审变化的资源只保留完成审阅所需的数据和具体路径核验，解决后再释放。重新纳入已释放路径时以稳定当前状态建立新基线，不恢复旧基线，也不推断离开范围期间的变化历史。
